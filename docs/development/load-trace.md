# Owner page load trace

Enable `POLYCORD_ENVIRONMENT=staging` and `POLYCORD_LOAD_TRACE_ENABLED=true` on the staging deployment. Leave `POLYCORD_PUBLIC_URL` unset. Production/public deployments remain disabled. Use an owner session from `POLYCORD_ADMIN_USER_IDS`.

For Netlify, apply these values to the serving staging site's production context and both function/edge scopes. The app's staging flag is distinct from Netlify's context name.

The shared locale layout shows the panel throughout the app. The guarded Discovery document and server app layout supply an owner-only bootstrap; owner responses are private and uncached. Direct entry counts from browser navigation, including the earlier blank wait. Links and the shared router start a new trace before the destination appears. Browser back/forward and refresh also restart timing. A document restored from the browser's back/forward cache counts from its restore event. Hash links, same-page filters, external links and links opened in another tab do not restart the current page trace.

Discovery finishes after its single bootstrap request, recorded under both the viewer and discovery phases, succeeds and the grid or empty result renders. Server app pages finish after their content hydrates, fonts settle and two animation frames run. Inbox additionally waits for its first notification response; an error or missing page finishes with a failed content phase. Settings, profile, saved, onboarding, member profiles, inbox, admin, analytics and legal routes report total server page preparation. Initial app layout account, settings, theme and staff work is reported separately. Parallel spans overlap, and cached navigation can reuse server preparation from an earlier request.

Each client navigation uses a new time origin and retains up to fifteen previous visits in memory. Superseded visits and pending requests are cancelled in the history; their late responses and paint callbacks cannot overwrite the next visit. The copy button exports the current trace and previous visits. A full reload starts fresh and clears history.

The panel records document/redirect/connection/first-byte timing, controls, viewer and discovery requests, reported gate and API spans, and deferred grid readiness. Same-origin fetch, script and stylesheet resource timings show response waits, browser-reported redirect duration and exposed server spans. Resource paths omit queries and member identities. A requested member alias and its committed destination appear in the navigation trail. Browser timing exposes aggregate redirect duration, not the URL or timing of every intermediate HTTP redirect. Resources can include background or prefetch activity overlapping the visit; they are observations, not additional durations to sum into the page total. No bodies, cookies or account values are exported. Nothing is stored or sent to an analytics service. API spans include connection/query work where the existing functions combine it; they do not represent isolated database engine execution.

Server spans arrive with each response. Time outside the reported gate/handler includes unexposed platform work, network/transfer and client processing and cannot be labeled purely Netlify or Supabase. Completion excludes remaining image downloads, animations and background work. Client transitions show routing time instead of reusing the first document's DNS, redirect or first-paint numbers. The native Discovery bootstrap is specific to the hosted Netlify adapter; the server app bootstrap also works locally. UI proof uses built Storybook states and isolated server/client lifecycle tests.

Disable the flag and redeploy to remove the diagnostic. No ban transport, database setting or deadline changes are required.
